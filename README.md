# Microsoft's code before and after AI

A reproducible test bench that runs hot paths of Microsoft .NET libraries across major versions 6 to 11, records [EmberTrace](https://www.nuget.org/packages/EmberTrace) traces, computes statistics, and links code changes to their authors (people vs the GitHub Copilot coding agent).

## Epochs

| epoch | versions | dates (GA) | why |
|---|---|---|---|
| E0 | 6.0.x, **7.0.x** (baseline) | 2021-11-08, 2022-11-08 | 7.0 is the last release written before ChatGPT (2022-11-30) |
| E1 | 8.0.x, 9.0.x | 2023-11-14, 2024-11-12 | AI assistants, no coding agent |
| E2 | 10.0.x, 11.0 | 2025-11-11, November 2026 (11.0 is at RC3) | the Copilot coding agent opens PRs in dotnet/runtime from 2025-05-19 |

Exact package versions are in `matrix/versions.json` (generated by `scripts/resolve-versions.py`); every checked fact and its source is in `docs/verified-facts.md`.

## Two tracks

- **Track A (primary): package version varies, runtime fixed.** `src/Harness` runs on .NET 10 and swaps the NuGet packages: `Microsoft.Extensions.DependencyInjection`, `Configuration` (+`Json`, `Binder`), `Options`, `Logging`, `Caching.Memory`, and EF Core + SQLite (6–10; EF Core 11 needs net11.0 and moved to Track B). All packages of a point share one major; the harness refuses to run (exit code 3) if a loaded assembly has another major.
- **Track B: library + runtime.** `System.Text.Json`, `Channels`, `Immutable`, ASP.NET Core and EF Core 10/11 live in (or depend on) the shared framework, so `src/Harness.TrackB` compares net10.0 with net11.0. The BenchmarkDotNet suite in `bench/Bdn` extends this to net6.0–net9.0 and labels every row "library + JIT".

Supporting pieces:

| folder | what it does |
|---|---|
| `src/Compare` | `.ember` → per-scope medians across processes, TraceDiff against the baseline, CSV/Markdown, hotspots, collapsed stacks, Chrome JSON |
| `analysis/` | bootstrap CIs, Mann–Whitney U, 5% noise rule, epoch plots (PNG + SVG) |
| `bench/Bdn` | BenchmarkDotNet mirror of both tracks (no EmberTrace) |
| `glassbox/` | DI and Caching.Memory compiled from two tags with scopes injected into internal methods |
| `attribution/` | commits between tags → pull requests → `cca` / `msft-human` / `community` (+ agent co-author flags), hot-method history, perf labels, reverts, servicing churn |
| `static-metrics/` | per-tag line counts, cyclomatic complexity, method length, nesting, analyzer warnings |

## Running

Requirements: Linux, the .NET 10 SDK on `PATH`, Python 3.12, git. The scripts install the .NET 11 SDK (and, for BenchmarkDotNet Track B, the 6.0–10.0 runtimes) into `.dotnet/` themselves, and the Python packages into `.venv/`.

```bash
./scripts/run-matrix.sh --quick          # smoke test: e0-7 and e2-10, 2 processes, 20 iterations, plus Track B
./scripts/setup-stand.sh                 # print the bench setup commands (apply with --apply), see docs/stand.md
./scripts/run-matrix.sh --runs 10        # full matrix: 6 Track A points + Track B, 10 processes, 200 iterations
./scripts/run-matrix.sh --runs 10 --no-tiering   # control run with DOTNET_TieredCompilation=0
./scripts/run-bdn.sh                     # BenchmarkDotNet cross-check (add --quick for short jobs)
./glassbox/run.sh v7.0.20 v10.0.14       # glass box: hotspots and flame graphs for two tags
./attribution/run.sh --library all       # attribution; set GH_TOKEN or log in with gh for 5,000 requests/hour
./static-metrics/run.sh                  # static metrics for the latest tag of every major
```

Useful options of `run-matrix.sh`: `--points e0-7,e2-10`, `--iterations`, `--warmup`, `--track a|b|all`, `--cpus 2-5`, `--include-new` (keyed services and the source-generated binder; not comparable with E0).

## Where results go

| path | content | committed |
|---|---|---|
| `results/raw/env.json` | machine state at the start (governor, turbo, kernel, `dotnet --info`) | no |
| `results/raw/<label>/<scenario>-<pid>.ember` | one EmberTrace trace per process and scenario | no |
| `results/raw/<label>/<scenario>-<pid>.run-meta.json` | loaded assembly versions, runtime, CPU, `DOTNET_*`, git sha, per-scope allocations | no |
| `results/summary/<scenario>.csv` / `.md` | per point and scope: median, p95, allocated bytes, runs, change vs baseline | yes |
| `results/summary/<scenario>-runs.csv` | per process values used by the statistics | yes |
| `results/summary/stats.csv` / `stats.md`, `plots/` | CIs, Mann–Whitney U, verdicts, epoch plots | yes |
| `results/summary/diff/`, `traces/` | TraceDiff texts, hotspots and collapsed stacks of a representative run per point | yes (Chrome JSON is not) |
| `results/summary/attribution*.csv`, `attribution.md` | attribution | yes |
| `results/summary/static-*.csv` | static metrics per tag | yes |
| `results/glassbox/<tag>/` | glass-box traces, hotspots, collapsed stacks | no |
| `results/bdn/` | BenchmarkDotNet reports | no |

## Threats to validity (short version)

The full list is in `docs/methodology.md`.

- Track A runs old package builds on the .NET 10 runtime: library code changes are isolated from the JIT/GC, but old packages may miss runtime-specific fast paths, and their in-box dependencies are always the .NET 10 copies.
- Track B and the BenchmarkDotNet suite cannot separate library from runtime.
- The scenarios are synthetic batches of APIs available in every version.
- `cca` means "pull request opened by the coding agent", not "code without human input"; `MEMBER` means dotnet organisation membership, not Microsoft employment; AI use that leaves no trace in git or GitHub is invisible.
- Differences under 5% are treated as noise, and a null result is an acceptable outcome.
- Numbers from a machine without the `docs/stand.md` setup are smoke-test output, not data.
